333 commits and four releases this week, v2.14.0 through v2.14.3. Two ways into the swarm from outside it became first-class: typed TypeScript for builders, and MCP for people working inside the assistant they already use. Routing and workflow code got portable at the same time, and a security sweep closed sender and permission gaps across every integration.

## Breaking Changes

Nothing was removed this week. These are tightenings: requests and writes that used to pass now need a linked sender, a principal, or a different executor, and each fails closed with an actionable error.

- **GitLab, Bitbucket and Azure DevOps mentions need a linked or allowlisted sender** ([#3541](https://github.com/desplega-ai/agent-swarm/pull/3541), [#3556](https://github.com/desplega-ai/agent-swarm/pull/3556)). Link the sender to a user or add them to the allowlist. Allowlisted actors with no linked user can still create tasks.
- **`/agent-swarm-status` honors the Slack sender allowlist** ([#3536](https://github.com/desplega-ai/agent-swarm/pull/3536)). Add the people who run status checks to the allowlist.
- **Identity routes called without a swarm key need a user or operator principal** ([#3445](https://github.com/desplega-ai/agent-swarm/pull/3445)). Send a user or operator credential.
- **Shared prompt-template writes, and repo `url`, `clonePath` or `hooks` changes, need a lead, operator or user** ([#3518](https://github.com/desplega-ai/agent-swarm/pull/3518), [#3413](https://github.com/desplega-ai/agent-swarm/pull/3413)). Route those edits through one of those principals.
- **QuickJS deployments refuse script workflow nodes and durable script runs** ([#3480](https://github.com/desplega-ai/agent-swarm/pull/3480), [#3419](https://github.com/desplega-ai/agent-swarm/pull/3419)). Keep those workloads on the native `SCRIPT_EXECUTOR`.
- **Schedule script arguments must be JSON objects** ([#3459](https://github.com/desplega-ai/agent-swarm/pull/3459)). Wrap scalar or array args in an object.

## Highlights

**A typed TypeScript SDK for the swarm API.** `@desplega.ai/agent-swarm-sdk` is a typed client for the swarm HTTP API, so an app, a script or a CI job creates tasks and reads results without hand-written fetch calls and hand-copied response shapes ([#3482](https://github.com/desplega-ai/agent-swarm/pull/3482)). Install it beside your other dependencies:

```bash
npm install @desplega.ai/agent-swarm-sdk
```

The PR is the reference for the API surface.

**Connect ChatGPT, Claude, Codex, Cursor and Grok over MCP.** The new user MCP guide covers a personal token and the client configuration for each assistant, so the swarm becomes a tool inside the app you already use ([#3449](https://github.com/desplega-ai/agent-swarm/pull/3449)). Read it at /docs/guides/user-mcp; signed completion webhooks are in /docs/guides/mcp-events.

**Model groups resolve wherever work starts.** One group name now resolves at `send-task`, on schedules, in workflow nodes and again at claim time, with group hops so a busy provider moves the task to the next member instead of failing it ([#3396](https://github.com/desplega-ai/agent-swarm/pull/3396)). Set the ladder once; the task carries it.

**Workflow logic runs in QuickJS.** Code-match nodes and string wait filters run sandboxed in QuickJS rather than on the native worker ([#3463](https://github.com/desplega-ai/agent-swarm/pull/3463)), limited to config interpolation sources so a node cannot read a trigger or an upstream output it was not given ([#3476](https://github.com/desplega-ai/agent-swarm/pull/3476)). Same workflow file, cheaper and safer evaluation. Docs: /docs/concepts/workflows.

**Follow-ups that land, and a gate that enforces.** Follow-up sends are optimistic with retry, and task creation is idempotent, so a retried follow-up no longer duplicates a task or disappears with the socket ([#3381](https://github.com/desplega-ai/agent-swarm/pull/3381)). The follow-up gate also gains an enforce mode ([#3479](https://github.com/desplega-ai/agent-swarm/pull/3479)), so shadow mode can become a real policy.

**Durable object scripts in the dashboard.** Durable object scripts, their objects and their object runs are now visible in the UI ([#3415](https://github.com/desplega-ai/agent-swarm/pull/3415)). An object's state and history stop being a SQL question.

## Bug Fixes

**Security**

- Public webhook receivers enforce a raw-body size limit ([#3538](https://github.com/desplega-ai/agent-swarm/pull/3538)).
- Every backlogged route declares its RBAC posture, and the route backlog is gone ([#3515](https://github.com/desplega-ai/agent-swarm/pull/3515), [#3514](https://github.com/desplega-ai/agent-swarm/pull/3514), [#3502](https://github.com/desplega-ai/agent-swarm/pull/3502), [#3477](https://github.com/desplega-ai/agent-swarm/pull/3477)).
- x402 reads the v1 `maxAmountRequired` before spending-limit checks and picks the signed amount field by protocol version ([#3521](https://github.com/desplega-ai/agent-swarm/pull/3521), [#3523](https://github.com/desplega-ai/agent-swarm/pull/3523)).
- The evals API refuses other-origin and non-JSON writes when it runs without a key ([#3532](https://github.com/desplega-ai/agent-swarm/pull/3532)).
- Connector code is served only to the exact connect page, and the dashboard asks before a top-level link switches connection ([#3525](https://github.com/desplega-ai/agent-swarm/pull/3525), [#3529](https://github.com/desplega-ai/agent-swarm/pull/3529)).
- A stored `CLAUDE_BINARY` stays out of the API process env, and generated shell commands quote URL and header values ([#3451](https://github.com/desplega-ai/agent-swarm/pull/3451), [#3411](https://github.com/desplega-ai/agent-swarm/pull/3411)).
- Tool-usage arguments bind as SQL parameters ([#3414](https://github.com/desplega-ai/agent-swarm/pull/3414)).
- Edited workflow script nodes run as their creator only after the creator or a lead saves, and signal routes refuse extension-bridged event names ([#3494](https://github.com/desplega-ai/agent-swarm/pull/3494), [#3486](https://github.com/desplega-ai/agent-swarm/pull/3486)).
