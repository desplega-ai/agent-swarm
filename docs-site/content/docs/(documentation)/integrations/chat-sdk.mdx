Agent Swarm can use [Chat SDK](https://chat-sdk.dev) as an input channel. One API process runs one Chat SDK instance for each configured adapter. The bespoke [Slack](/docs/integrations/slack), [AgentMail](/docs/integrations/agentmail) and [Kapso](/docs/integrations/kapso) integrations are not changed.

<Callout type="warn">
**Status: Telegram, Slack and Teams.** The Discord adapter is bundled but not yet supported.
</Callout>

## What it does

- **Inbound on mention or DM.** A bot mention or a direct message creates a task for the Lead with `source: "chat"`.
- **Thread identity.** The task gets a context key of the form `task:chat-sdk:{adapter}:{encoded thread id}`. Later tasks for the same thread share this key.
- **State in SQLite.** Chat SDK state (subscriptions, locks, dedupe keys, message history) lives in dedicated `chat_*` tables in the swarm database.
- **Signature checks by the adapter.** The webhook endpoint is public. The adapter checks the platform signature (for Telegram, the secret token header) before it reads the update.

## Configuration

Set two keys, as environment variables or on the dashboard (**Settings → Configuration**). Both take effect after an API restart.

| Key | Value |
|---|---|
| `CHAT_SDK_ENABLED` | `true` to start the channel. Default `false`. |
| `CHAT_SDK_ADAPTERS` | JSON object. Each key is an adapter name, each value is the adapter config. |

A value can reference another config key as `{"$config": "KEY"}`. The API resolves the reference at boot from the global swarm config (secrets included). It never reads the reference from the process environment, and it rejects reserved keys such as `API_KEY`. For env-only deployments, put the raw values in `CHAT_SDK_ADAPTERS`.

```json
{
  "telegram": {
    "botToken": { "$config": "TELEGRAM_BOT_TOKEN" },
    "secretToken": { "$config": "TELEGRAM_WEBHOOK_SECRET" },
    "mode": "webhook",
    "userName": "my_swarm_bot"
  }
}
```

The API refuses `apiUrl`, `apiBaseUrl`, `webhookVerifier` and `allowUnverifiedWebhooks` in this JSON. These keys would send secrets to another host or skip the signature check.

### Telegram fields

| Field | Required | Notes |
|---|---|---|
| `botToken` | yes | The token from BotFather. |
| `secretToken` | in webhook mode | Telegram sends it in the `X-Telegram-Bot-Api-Secret-Token` header. |
| `mode` | no | `webhook` (default) or `polling`. Use `polling` for local development without a public URL. |
| `allowedUserIds` | no | Telegram user ids allowed to trigger the bot. All users are allowed when empty. |
| `userName` | no | The bot username, used for mention detection. Default `swarm`. |

### Slack fields

The Chat SDK Slack adapter and the built-in [Slack](/docs/integrations/slack) integration cannot run together. Set `SLACK_DISABLE=true` to use this adapter. Without it, the API logs the conflict at boot and does not start the Chat SDK channel.

| Field | Required | Notes |
|---|---|---|
| `botToken` | yes | The bot token (`xoxb-...`). |
| `mode` | no | `webhook` (default) or `socket`. |
| `signingSecret` | in webhook mode | The app signing secret. The adapter checks the `X-Slack-Signature` header with it. |
| `appToken` | in socket mode | The app-level token (`xapp-...`) with `connections:write`. |
| `userName` | no | The bot name. Default: the name from `auth.test`. |

In webhook mode, set the app's Event Subscriptions request URL to the webhook URL below. The adapter answers Slack's `url_verification` challenge. In socket mode, the adapter opens the Socket Mode connection at boot, and the webhook URL answers `405`.

### Teams fields

| Field | Required | Notes |
|---|---|---|
| `appId` | yes | The Azure Bot app (client) id. |
| `appPassword` | yes | The app client secret. |
| `appType` | no | `MultiTenant` (default) or `SingleTenant`. |
| `appTenantId` | for `SingleTenant` | The Entra tenant id. |
| `userName` | no | The bot name. |

Set the Azure Bot messaging endpoint to the webhook URL below. The adapter checks the Bot Framework token on every request. A Teams start failure marks only the Teams adapter as failed. The other adapters keep running.

### Webhook URL

Each adapter has its own webhook URL:

```
{PUBLIC_MCP_BASE_URL}/api/integrations/chat/{adapter}/webhook
```

For Telegram, register it with the Bot API:

```bash
curl "https://api.telegram.org/bot<token>/setWebhook" \
  -d "url=https://<your-api-host>/api/integrations/chat/telegram/webhook" \
  -d "secret_token=<secretToken>"
```

The endpoint answers `404` when the channel is off or the adapter is not configured. It answers `503` when the adapter is configured but failed to start (see the API boot log).
