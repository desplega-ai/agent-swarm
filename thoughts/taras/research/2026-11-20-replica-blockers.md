# What stops a second API replica on one Postgres database

**Summary.** The API assumes it is the only process: in-process buses carry events between requests, in-memory maps act as locks and claim sets, and boot code treats every `running` row as left over from a dead process.
Postgres with D6 (SERIALIZABLE plus retry) makes the row-level claims safe across processes. It does not fix the in-memory state, the boot recovery, or the per-pod disk state listed here.
Counts: event buses 9, in-memory locks and claim sets 14, caches and module state 9, timers and loops 20, single-writer assumptions 8, connection registries 7. Total 67.

Branch `feat/postgres-storage-engine` at `f33ff56dc`. Scope: API-server code only (`src/http`, `src/be`, `src/workflows`, `src/slack`, `src/realtime`, integrations, `packages/storage*`, the chart). Worker-side code is out of scope.

Severity used in each entry:

- **A**: wrong result or lost work (a run resumed twice, a live task failed, a security revocation that does not reach every socket).
- **B**: a duplicate external side effect or extra cost (a second Slack post, a second runtime, a second Lead task).
- **C**: duplicate idempotent work only (wasted queries, more SERIALIZABLE retries).

"Later goal" is a one-line pointer, not a design.

## 1. In-process event buses and pub/sub (9)

Both buses deliver only inside the process that emits. An emit runs after COMMIT on the replica that committed the change. A subscriber that reacts to *its own* commit still works, because that replica runs the reaction exactly once (see "Not blockers"). The entries below are subscribers that need events from *every* replica, or that keep state from an earlier event.

## Not blockers

Each item was checked and is safe with two replicas, for the reason given.

- **Encryption key in memory** (`src/be/crypto/key-bootstrap.ts:23`): `cachedKey` does not change after load. It is safe when every replica gets the same key (5.3).
- **Prompt templates**: `resolvePromptTemplate` (`src/be/db.ts:9099`) reads `prompt_templates` on each call. The code registry (`src/prompts/registry.ts:27`) holds definitions set at module load, which do not change.
- **RBAC**: no permission or role cache in `src/rbac/` or `src/be/rbac-roles.ts`. `can()` reads on each call. `src/be/rbac-roles.ts:167` only remembers which warnings were logged.
- **Pricing**: cost recompute reads the `pricing` table. Only the refresh single-flight (`src/be/pricing-refresh.ts:225`) is per process (4.17).
- **Tracker OAuth refresh** (`src/oauth/ensure-token.ts:99-128`, `:253`): the `refreshLocks` map only queues callers in one process. The cross-process guard is the DB lease `acquireOAuthRefreshLock`.
- **Slack inbound receipts** (`src/be/db-queries/slack-inbound.ts:10-22`): admission is one atomic INSERT against a unique dedup key, so a delivery to either replica creates one row. The boot recovery of these receipts is a blocker (4.11).
- **Jira webhook dedup** (`src/jira/webhook.ts:9`, `:60`) and **tracker delivery state** (`src/be/db-queries/tracker.ts:183`) are persisted in the DB.
- **Chat SDK relay and state**: `markChatRelayAttempted` (`src/be/db/tasks/read.ts:1018-1035`) is a conditional UPDATE, and the watcher skips the send when it returns false (`src/integrations/chat-sdk/relay.ts:238`). The `StateAdapter` (`src/integrations/chat-sdk/state.ts`) is DB-backed, with TTL locks.
- **Draft and attachment leases** (`src/slack/inbound-files.ts:363`, `src/integrations/chat-sdk/attachments.ts:248`): renewed in the DB. The sweep honors them on any replica.
- **Deferred task waits** (`src/scheduler/deferred-task-waits.ts:443-461`): fixed listeners read durable waits, the claim in `dispatchDeferredTaskWait` wakes each wait exactly once (`:320-330`), and the scheduler poll reconciles waits that another replica's event did not reach. `confirmFlights` (`:332`) only shares provider reads.
- **Workflow-bus subscribers that react to their own commit**: the resume listeners (`src/workflows/resume.ts:122-186`), event triggers (`src/workflows/index.ts:71`), Linear, Jira and Azure outbound (`src/linear/outbound.ts:49-53`, `src/jira/outbound.ts:67-70`, `src/azure-devops/outbound.ts:87`), MCP Events delivery (`src/be/mcp-events/dispatcher.ts:189-190`, subscriptions in the DB), the task auto-title (`src/be/task-auto-title-listener.ts:82`), and the Slack render events (`src/slack/render-v2.ts:2643`). The emit runs post-commit on the committing replica, which runs each reaction once. The exceptions are 1.8, 1.9, 2.11 and 3.5.
- **Agent-fs object webhooks** (`src/be/primitives/object-webhooks.ts:78`, `:142`): one replica registers through a DB claim with a lease. `reindexing` (`src/be/primitives/objects.ts:107-108`) only allows duplicated safe work, as its comment says.
- **Telemetry ingest anchor** (`src/be/telemetry-ingest-anchor.ts:44-62`): the in-memory `known` value only skips DB reads. The write re-checks inside a transaction.
- **Pool task assignment** (`src/be/db/tasks/write.ts:229-262`): capacity is re-checked in the write, so two routing sweeps cannot over-assign (4.9 is only extra scans).
- **Values that do not change per deployment**: the Slack, Azure, Bitbucket and Jira bot identity caches (`src/slack/handlers.ts:256`, `:261`; `src/slack/assistant.ts:42`; `src/azure-devops/api.ts:49`; `src/bitbucket/api.ts:21`), the GitHub App installation token cache (`src/github/app.ts:11`, `:20`; each replica mints valid tokens), the constant Sets and Maps (validators, tool lists, reserved keys), and the OpenAPI spec memo (`src/http/openapi.ts:16`). A webhook secret that is rotated through config is covered by 3.1.
- **TTL-bounded read caches**: `src/http/usage-cache.ts:24`, `src/be/savings/read.ts:155`, `:360`, `src/be/skill-usage.ts:21`, `src/http/savings.ts:384`, `:559-576`, `src/http/tool-schema-estimate.ts:74`, `src/http/fleet-benchmark.ts:94`. They are read-only, and the TTL bounds the staleness.
- **Per-process diagnostics and per-connection timers**: the event-loop lag probe (`src/be/event-loop-lag.ts:116`), the explicit GC and idle MCP transport sweep (`src/http/index.ts:249`; it closes only this process's transports), the realtime ping (`src/realtime/transport.ts:555`), the script executor heartbeat (`src/script-workflows/executor.ts:422`), the typing keepalive (`src/integrations/chat-sdk/typing.ts:48`), the Slack socket watchdog (`src/slack/app.ts:275`), and the RBAC audit flush buffer (`src/be/rbac-audit.ts:214`; each replica flushes its own rows).
- **Extension bridge secret** (`src/extensions/dispatcher.ts:60`): it authenticates loopback calls from a process to itself.
- **Slack Socket Mode with two connections**: Slack spreads events over the open connections of one app, and the durable receipts dedupe them. I did not test this end to end.
