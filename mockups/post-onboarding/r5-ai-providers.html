AI providers, round 5: one list, an Add menu with a side panel, four tabs

Taras's round-4 notes, applied to one page. LLMs shows every configured provider in one list. Add provider opens a searchable menu of every provider the swarm supports. A pick opens a side panel with the setup steps and the fields. System One, Embeddings and Transcription get their own tabs.

  • Tab row. LLMs, System One, Embeddings, Transcription. The search and the primary action sit after the tabs, as on Tools. Embeddings and Transcription hold one setup each, so they have no search.
  • LLMs. One row for each configured provider: mark, name, the harnesses that use it, type, key count, status, and the cost today and over 7 days. Click a row to show its keys. The key columns line up under the provider columns.
  • Add provider. 16 providers in three groups. A provider that is already set up shows its key count. A pick on it adds one more key.
  • Side panel. The setup steps from the code and docs, the fields with their config keys, and Test and add. The API tests most keys with the vendor before it saves them.
  • Data. Only what the API returns today, with no "not yet supported" tags. Usage windows show only for Claude subscription tokens. Unconfigured providers live in the Add menu, not in the list.

The desktop states need a window wider than 760px. The phone frames follow.

(1) LLMs: four configured providers, one expanded

Claude subscription is open. The token taras-backup hit its 5 h window, so the row says 1 rate limited. The DeepSeek key fails its live check, so the LLMs tab has a red dot. Totals sit in the last row.

(2) Add provider: the searchable menu

Subscriptions, API keys, and gateways or OpenAI-compatible endpoints. Each row shows the harnesses that use the provider. A check marks a provider that is set up. Type to filter. Enter or a click opens the side panel.

(3) Side panel: Claude subscription

Steps from the setup card, the token field with its config key, an optional name and plan, and Test and add token. The format check runs while you type. Click Test and add token to see the live check.

(3b) Test and add: the results

The panel footer after a click on Test and add. POST /api/config/pool-keys tests the key with the vendor first. A rejected key is not saved. Amp, Cursor and Devin keys have no live check, so a worker checks them.

(4) System One: hosts and defaults

Five hosts. Three have credentials. The defaults sit on top: decisions use SYSTEM_ONE_DEFAULT_PROVIDER, and extraction has one host only. Set up and Edit open the same side panel.

(5) Embeddings: the memory setup

The provider, model and size that memory uses now, the last test, and what a change does to the memories that exist. Change provider opens the presets from the /setup memory step.

(6) Transcription: voice notes into task text

The active provider and where its key comes from, the auto-detect order, and the stored values under Advanced. Change provider pins a provider or sets a key of its own.

Same Sheet as (3). Set up on laya in (4), Change provider in (5) and in (6). The frames above open them live.

Where the data comes from

Paths are relative to the repo root. Read in the worktree on 2026-11-04.

  • LLMs and the Add menu. The llm entries in apps/ui/src/lib/integrations-catalog.ts, the registry in packages/model-catalog/src/openai-compatible-providers.ts (NaN, Helmcode, Vercel AI Gateway, <ID>_BASE_URL), and CREDENTIAL_POOL_VARS in src/utils/credentials.ts (adds DeepSeek, xAI, Amp, Cursor, Devin), which src/http/pool-keys.ts accepts.
  • Steps and field text. apps/ui/src/pages/setup/steps/ai/claude-card.tsx, codex-card.tsx, devin-card.tsx, open-harness-card.tsx, the key prefixes in KEY_RULES (autosave-secret-field.tsx), and the docs guides/provider-auth/*.mdx.
  • Test and add. POST /api/config/pool-keys returns verified, rejected (HTTP 422, nothing saved) or not_tested. Live probes in src/utils/provider-key-probes.ts: Claude token, Anthropic, OpenAI, OpenRouter, DeepSeek, xAI and the OpenAI-compatible registry.
  • Key rows. ApiKeyStatus in apps/ui/src/api/types.ts (plan, planSource, rateLimitedUntil, lastUsedAt, lastValidationError, rateLimitWindows) and the costs from /api/keys/costs and /api/usage/summary, as in round 4.
  • System One. SYSTEM_ONE_HOSTS in src/workflows/executors/system-one-providers.ts (hosts, decide or extract, default models, key names), SYSTEM_ONE_DEFAULT_PROVIDER in apps/ui/src/lib/configuration-catalog.ts, and concepts/workflows.mdx (laya setup, Cloudflare account ID). Extraction has no config key: SYSTEM_ONE_EXTRACT_DEFAULT_PROVIDER is a constant.
  • Embeddings. PRESETS and errorHint in apps/ui/src/pages/setup/steps/step-memory.tsx, the catalog entry memory, src/http/onboarding.ts (a reused key is copied into EMBEDDING_API_KEY), and src/be/memory/boot-reembed.ts (only rows with no vector or the wrong size get a new one).
  • Transcription. apps/ui/src/lib/transcription-status.ts, components/integrations/transcription-section.tsx and the catalog entry transcription (default models, base URLs, write-only key).
  • Marks. Inline copies of apps/ui/public/provider-logos, harness-logos, integration-logos and the shapes in components/shared/provider-icon.tsx. A provider with no mark in the app gets a letter.
