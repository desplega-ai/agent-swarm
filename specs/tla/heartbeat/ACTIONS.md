# Heartbeat model: action map

Every TLA+ action maps to the code path it models and the SQL guard it relies on. Line numbers are for `main` @ `0f027670`. Since #3562 the SQL of every modeled write lives in the storage repositories (`packages/storage/src/repositories/tasks.ts` and `agents.ts`, with per-engine overrides in `packages/storage-sqlite/` and `packages/storage-postgres/`), shared by the SQLite and Postgres engines. The functions named below are the `src/be` wrappers that call them, and each guard below is the repository statement's WHERE clause on both engines. Postgres runs transactions at SERIALIZABLE with retry on serialization failure, so a retried transaction is still one atomic step; the two READ COMMITTED exceptions on modeled paths (the poll write pass and the finish route) are covered in the `ClaimRead`, `PollStart` and `Complete` rows. A counterexample is only acted on if every step in its trace maps to a row here. Since #3679 `getTaskById` and `getAgentById` (`src/be/db/tasks/read.ts:425`, `src/be/db/agents.ts:222`) may serve a row read up to 250 ms earlier in the same HTTP request (`src/be/request-memo.ts`; any in-process write to `agent_tasks` or `agents` invalidates it, and a read inside a transaction bypasses it). No modeled guard changes: a cached row only makes a JS pre-check outside a transaction read earlier, every modeled write still decides on its own SQL WHERE, and the model already lets other actions run between a read and the write that follows it.
