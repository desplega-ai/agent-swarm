# Heartbeat model: action map

Every TLA+ action maps to the code path it models and the SQL guard it relies on. Line numbers are for `main` @ `60ce0bcb`. A counterexample is only acted on if every step in its trace maps to a row here.

### Runtime pools (#2045, `RUNTIME_POOLS`)

`RUNTIME_POOLS_ENABLED` defaults off, so `Heartbeat.cfg` sets `RUNTIME_POOLS = FALSE`; run with `RUNTIME_POOLS=TRUE` to check the pool paths. A pool agent without a runtime is modeled as a worker that is not alive.

### Workflow agent-task steps (#2262, `WORKFLOW_STEP`)

`Heartbeat.cfg` sets `WORKFLOW_STEP = FALSE` (the root is a plain task); run with `WORKFLOW_STEP=TRUE MaxGen=1` to make the root a workflow agent-task step. `MaxGen=1` is the one retry `SUPERSEDE_RETRY_POLICY` gives a cut step, and it keeps the graph at 10,679,820 states (15,007,564 before #3008 dropped the reboot-retry child of a step task, 14,122,316 before the #2970 generation choice in `DrainHandoff`); with the cfg's `MaxGen = 2` the late relabels interleave with every other action (7,130,228 states at `NTasks=2`, against 452,476 without the flag, both measured before #2970) and the full-size check does not finish. `cut[t]` is the step state of a row: `none` (not a step task), `step` (bound to its step), `cut` (`failed` with `failureReason = 'superseded_workflow_task'`, written by `HbWrite`, `DrainHandoff` or `RuntimeRecover`), then `queued`, `retried` or `absorbed`. Resume and reroute children are plain tasks (`none`): `createTaskExtended` copies no `workflowRunStepId` from the parent. A reboot-failed step task gets no reboot-retry child (#3008).
